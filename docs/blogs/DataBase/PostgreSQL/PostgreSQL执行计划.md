# PostgreSQL执行计划
## 总体思路
1. 先看底部的 Execution Time：知道总耗时。
2. 从下往上找 actual time 最大的节点：谁最耗时，谁就是嫌疑人。
3. 盯着 loops= 看：如果 loops 很大，乘以单次时间，就是总灾难时间。
4. 盯着 Seq Scan（全表扫描）看：大表上面看到这个，立刻找 Filter 里的字段，去建索引！
5. 看 Rows Removed by Filter：这个数字越大，说明白扫的行数越多，越需要索引。

## 大表定义
- **小表（1万 - 50万行）**：随便造，全表扫也就几十毫秒。
- **中表（50万 - 1000万行）**：开始需要认真建索引了，乱写 SQL 会卡顿。
- **大表（1000万 - 1亿行）**：属于绝对的大表。必须精细化建索引，复杂查询要考虑分区（Partitioning）或者物化视图。
- **超大表（1亿行以上）**：没有分区、没有冷热数据分离，基本没法玩。
