### 业务办件流程
#### 1 政府投资类新建

#### 核心认知：两段式状态机，前段不碰 Activiti

**初步审查这一整段流程不创建 Activiti 任务**。走件完全靠"双状态机 + 收件关系表"驱动，Activiti 流程实例要到**项目策划**环节才创建（`hatchProjectSuccess`）。

涉及的 4 张关键表：

|表|作用|
|---|---|
|`PCC_PROJECT.PROCESSSTATE / LIFESTATE`|主状态机|
|`BZ_PROJECTCASE.PROJECTSTATE`|案件状态，所有箱子列表过滤用|
|`BZ_SPECIALSENDRELATION.RECEIVEUSERID`|**派件箱取数的唯一凭据**|
|`PCC_PROJECTOPERATE`|操作留痕，已办箱靠它（opttype=提交 + activityname=初步审查）|

#### 阶段 1：新建（谋划库）

- 入口：`governmentController.js:268` `doCreate` → `startProcess=false`，初始状态=**谋划**，只落库不启动流程。
- 谋划库列表过滤：`governmentController.js:62` `projectState=["谋划","初步审查不通过","退件"]`——被退回的件也回到这里。
- 双击可编辑条件：`rowDblClick`（`governmentController.js:236`），仅谋划/初步审查不通过/初步审查通过可编辑，其余只读。
- 件所在位置：去到新建人“政府投资类”箱子中。

#### 阶段 2：发送 = 登记收件人

- 前端：`governmentController.js:177` `$scope.specialSend` → `projectBuildCommonService.specialSend`（URL 映射在 `projectBuildCommonConstant.js`：`pcc/extProjectbuild/specialSend`）
- 后端：`ExtProjectBuildServiceImpl.java:105` `specialSend`
    - 写 `BZ_SPECIALSENDRELATION`（收件人=派件箱的主人）
    - 状态 → **派件**
    - 同时写 `pcc_projectoperate`：`opttype=提交` + `activityname=初步审查`——**这是已办箱的过滤键**，两处键值必须一致
    - 未选定接收人时直接 return（`isProjectBuild` 分支），避免产生无收件人的派件
- 件所在位置：发送提交的目标人的“初步审查”派件箱。

#### 阶段 3：派件箱办理 / 退件（派件）

- 派件箱列表：`getCbscBoxTodoList` 动态 SQL（`dynamicsql/projectbuild.xml`），`filterByUser` 按 `BZ_SPECIALSENDRELATION.RECEIVEUSERID` 过滤，`projectState=["派件"]`（`boxReceiveCtrl.js:27` prePlanning 分支）
- **办理（即派件）**（`boxReceiveCtrl.js:108` `applyProject`）：`specialDeliveryProject(type=初步审查)` → 后端 `ExtProjectBuildServiceImpl.java:687`——状态 → **初步审查**，收件人改派给办理人，进办理人的待办箱。全程无 Activiti。
- **退件**（`boxReceiveCtrl.js:202` `rejectionProject`）：`specialDeliveryProject(type=退件)`，固定退回创建人

#### 阶段 4：待办箱定结论（初步审查通过/不通过）

- 环节需要填写意见
- 待办箱：`projectState=["初步审查"]`（`boxTodoController.js`），表单 `from=prePlanning-boxTodo`
- 前端：`formHandlingController.js:176` `$scope.send` 是统一入口——先保存校验，再分流：
    - `getProjectReviewCommentInfo`（`formHandlingController.js:763`）校验审查意见：`result=success→通过`、`failure→不通过`
    - 通过后调 `prePlanning` API
- 后端：`ExtProjectBuildServiceImpl.java:262` `prePlanning`
    - 通过 → 状态=**初步审查通过** + **项目储备**（进储备库）
    - 不通过 → 状态=**初步审查不通过** + **项目谋划**（退回谋划库）
- 通过后，进入到当前办理人员的”项目储备库“的”社会投资类“TAB页下。

#### 阶段 5：储备库启动策划（创建 Activiti 流程）

- 储备库列表：`governmentController.js:73` `projectState=["初步审查通过","策划失败"]`
- 启动策划：`startActivityUsers`（`ExtProjectBuildServiceImpl.java:198`）→ **此处才创建 Activiti 流程实例**（项目策划流程）
- 策划完成回调 `hatchProjectSuccess`（`:321`）：成功→**实施库**（`:85` 列表 `projectState=["策划成功"]`，`intoProjectImplementation`）；失败→**策划失败**退回储备库

#### 已办箱的留痕逻辑

`boxDoneController.js` 按 `opttype='提交' + activityname='初步审查'` 过滤 `pcc_projectoperate`——因为发送派件动作写入了同键值记录，所以发送者在已办箱能看到这条件。**改这里任何一处键值，已办箱就会空**。

#### 回退（deleteSpecialSend）

`PdsSendServiceImpl.deleteSpecialSend`（两端共用）：删收件关系 + 写入发改委初审/自然资源部门初审"不同意"意见。前端分流在 `formHandlingController.js` `sendBack`：发改初审/自然资源部门初审走 `deleteSpecialSend`，其他走通用回退。
